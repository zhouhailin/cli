# cli 项目宪法

## 核心原则

### I. 自管理目录优先
所有工具链安装在 `~/.devkit/` 自管理目录内（sdkman/nvm/volta 模式），支持多版本共存与 `cli use` 版本切换；不污染系统目录，卸载即删目录。服务型软件（Redis/MySQL）的数据与配置同样位于自管理目录内。

### II. 交互式安装（NON-NEGOTIABLE）
所有安装命令必须提供清晰的交互式选择（发行版/版本/配置项），选项可预测、可取消；关键操作（覆盖安装、服务注册、卸载）必须二次确认。交互文案与错误信息一律使用中文。

### III. 跨平台一致性
macOS / Linux / Windows 三端行为一致，平台差异收敛在 `core/platform` 模块内；平台不支持的子命令必须给出明确的中文错误提示（如 Windows 上安装 Redis）。

### IV. 测试优先（NON-NEGOTIABLE）
TDD 强制：先写测试 → 用户批准 → 测试失败 → 再实现；Red-Green-Refactor 循环严格执行。核心逻辑（版本解析、配置读写、环境注入、服务文件生成）必须覆盖单元测试；下载/解压/安装流程使用 mock HTTP 服务做集成测试。

### V. 安全与完整性
下载必须校验 SHA-256（发行版提供时）；安装采用临时文件 + 原子重命名；MySQL root 密码交互输入不回显、仅存本地 `my.cnf`（权限 600）；任何凭据不得写入 config.json 或上传远端。

### VI. 简洁性
YAGNI：不提前实现未确认的功能；每个模块单一职责；宁可删除多余功能也不保留"可能有用"的代码。

## 工程约束

- **语言**：Rust（单二进制分发，clap 命令框架）
- **文档语言**：所有规格文档、任务清单、设计文档、README、代码注释一律使用中文
- **版本管理**：语义化版本；自更新通过 GitHub Releases 发布三端预编译二进制
- **国内环境**：默认配置国内镜像（Go 的 GOPROXY 为 goproxy.cn，Maven 可选阿里云源），同时保留官方源切换能力

## 开发流程

- 规格驱动：功能必须先有 spec（.specify/ 下归档），再计划、再任务、再实现
- 质量门禁：实现阶段必须附带测试；提交前运行 `cargo test` 与 `cargo clippy` 零警告
- 服务型功能（Redis/MySQL）必须先生成服务单元文件并通过内容断言测试，才能触碰真实服务注册逻辑

## 治理

本宪法高于其他任何实践；修订需记录版本与日期并经用户批准。所有 PR/评审必须核对宪法合规性；复杂度必须有理由；开发期运行时指引见 `.specify/memory/` 下其他文档。
